Automated Web Scanner

Programmed a Python script to audit sites for secure headers and CORS flaws.

1. Abstract

Many web application attacks, such as clickjacking, cross-site scripting, protocol downgrade and cross-origin data theft, succeed because of simple server misconfigurations. The Automated Web Scanner is a Python-based tool that automatically audits a website's HTTP responses for missing or weak security headers, insecure cookies, information leakage and CORS (Cross-Origin Resource Sharing) flaws. It produces a security score, a letter grade and clear fix recommendations, so that developers and students can improve a site's security quickly without manual inspection.

2. Introduction

HTTP security headers instruct the browser how to behave when handling a site's content. When they are missing, browsers fall back to permissive defaults that attackers can abuse. Similarly, a badly configured CORS policy can let a malicious website read private data from another site through the victim's browser.

Checking these settings by hand for every site is slow and error-prone. This project automates the process with a script that sends safe, read-only requests and analyses the responses.

3. Objectives

  • Automatically detect missing and weak HTTP security headers.
  • Identify CORS misconfigurations such as reflected origins and wildcard-with-credentials.
  • Audit cookies for Secure, HttpOnly and SameSite flags.
  • Detect information-leaking headers such as Server and X-Powered-By.
  • Provide a numeric score, letter grade and practical remediation advice.
  • Offer both a web interface and a command-line mode.

5.1 Security header analysis

The scanner requests the target page and inspects seven headers: HSTS, Content-Security-Policy, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy and Cross-Origin-Opener-Policy. It also checks quality, for example a short HSTS max-age or a CSP containing 'unsafe-inline'.

5.2 CORS testing

The scanner repeats the request with a crafted Origin header (an arbitrary origin, null, and a look-alike domain) and checks whether the server reflects it in Access-Control-Allow-Origin, and whether Access-Control-Allow-Credentials: true is also returned. A preflight OPTIONS request checks for unsafe allowed methods.

5.3 Cookie and leakage checks

Every Set-Cookie header is checked for the Secure, HttpOnly and SameSite attributes, and response headers are checked for exposed server versions.

5.4 Scoring

The score starts at 100 and points are deducted for each finding according to severity.

8. Ethical and Legal Considerations

The scanner must only be used on websites owned by the user or where written permission has been given. It performs passive, read-only requests and does not attempt exploitation, but unauthorised scanning can still violate laws and terms of service.

9. Limitations

  • Scans only the single URL provided, with no crawling of other pages.
  • Does not test for SQL injection, XSS or authentication flaws.
  • Results reflect the headers sent in response to the scanner's own requests, which may differ from those a browser receives.

10. Future Scope

  • Crawl multiple pages and subdomains.
  • Add TLS/SSL certificate and cipher analysis.
  • Export reports as PDF or JSON.
  • Store scan history in a database and show trends.

11. Conclusion

The Automated Web Scanner shows how a short Python program can find common, high-impact web misconfigurations in seconds. By checking security headers, cookies and CORS policy and presenting clear fixes, it helps developers harden their sites and helps students understand practical web security.
